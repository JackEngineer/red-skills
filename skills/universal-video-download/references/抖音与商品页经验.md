# 抖音与商品页下载经验

普通视频由 ../scripts/douyin.py 处理。商城页是浏览器辅助流程，不是自动脚本能力。下面是实际积累的处理规则。

## 执行顺序

1. 解析用户本次消息中的每一个链接，跟随短链跳转后再判断类型；短链本身不能证明它是普通视频。多链接分别记录目标与结果，用户纠正目标后不得继续发送旧文件。
2. 普通视频从最终路径 `/video/<编号>` 提取编号。先访问首页建立会话，再请求 `/aweme/v1/web/aweme/detail/?aweme_id=<编号>&aid=1128&cookie_enabled=true&platform=webapp`。解析前检查响应非空且为 JSON，接口空响应不代表视频不存在。
3. 详情接口无数据时，使用桌面浏览器 User-Agent 打开真实视频页，导航前注册 response 监听，捕获包含 `aweme/detail` 的响应 JSON；等待页面加载后再读取。此路径已实际成功，不要只在移动分享页和同一空接口间循环。
4. 若仍无详情，解析页面 script 内的 JSON 和 URL 解码 JSON，递归查找同时含 `video` 与 `desc` 或 `aweme_id` 的对象；也可检查分享页公开状态。核对 aweme_id 与目标编号以及标题，避免下载推荐视频。
5. 从 `download_addr`、`play_addr` 依次收集所有 URL 并去重。用 `curl -L --fail --max-time 180`，带 User-Agent 和 Referer；必要时使用本次会话 Cookie。每个候选最多尝试一次，403 后换地址，不原样循环。下载到 `.part`，成功且验证通过才保留为最终视频。不要假设 download_addr 一定无水印。
6. 商品详情页检查内置播放器，必要时点击封面使媒体控件出现，再使用“更多媒体控件 → 下载媒体”。确认新增文件和当前商品匹配；不能因静态 HTML 无 mp4 就要求用户另找链接。
7. 优先使用可用的 Playwright 浏览器；运行文件缺失时可选择已安装系统 Chrome 的 executable_path。不要为下载修改用户现有浏览器会话或配置。
8. 统一保存到 `~/Downloads/douyin/`，使用简短中文主题名，去掉换行、控制字符、斜杠、标签、表情和多余空格，冲突时追加视频编号。临时文件用当前 scratch 目录，不依赖旧临时脚本仍存在。
9. 用 `ffprobe -v error -show_entries format=duration,size:stream=codec_type,codec_name -of json <文件>` 检查大小、时长和视频流；必要时抽帧核对内容。成功返回命令不等于媒体正确，HTML 错误页不能充当视频。
10. 发送单独一行 `MEDIA:/绝对路径/简短文件名.mp4`，附约略时长与大小即可，不重放操作过程。没有平台回执时只说“已下载并核对，文件如下”，不得说“微信已收到”。用户报告未收到时先查实际投递记录，不能直接断定大小超限或文件名是根因。

## 大文件处理

- 先核对当前通道真实限制；约 80–100 MiB 只能作本地压缩触发策略，不是微信官方硬限制。
- 保留原件，另产微信版。预算视频码率约为 `目标字节数*8/时长/1000 - 音频及封装余量`，压缩后重新核对真实大小和完整时长。
- macOS 已验证可用 `ffmpeg -i <原件> -vf scale=720:-2 -c:v h264_videotoolbox -b:v <预算>k -c:a aac -b:a 64k -movflags +faststart <微信版>`；不可用时先查询现有编码器再选替代。
- 不把压缩、拆分或发送描述成已完成，除非真实运行并验证。

## 沟通与停止条件

用户希望收到微信可打开的文件，而非仅有下载位置。商品页有公开内置视频时主动寻找，不让用户重复做已能自动完成的步骤。用户明确取消后立即停止该目标；下一次请求只处理新链接。失败时用中文说明卡在哪一层，不以过程消息掩盖未交付结果。
