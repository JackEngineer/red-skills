# 小红书小工具开发指南

## 对话命令

用户可以在新对话输入 `$xhs-minitool-guide help` 或 `$xhs-minitool-guide guide`。已在使用本指南时，直接输入 `help` 或 `guide` 即可。只有当首个独立词是命令且上下文指向本指南时才按命令处理；需求正文中出现 help 或 guide 按普通文字理解。

**help**：直接用中文给出下面的菜单和示例，到此结束。用户只想查用法时，无需询问项目或展开能力表。

| 我想做什么 | 可以输入 |
| --- | --- |
| 看用法 | `help` |
| 浏览平台能力和限制 | 小红书小工具能做什么？ |
| 从零开始构思 | `guide` |
| 判断自己的点子 | `guide 我想做一个拍照打卡、退出后也能记路线的小工具` |

**guide [想法]**：进入开发向导，沿用对话里已有的目标。有想法就直接按下文「收到功能需求后」逐项判断，给一个能先做出来的最小版本，以及一个能验证核心功能的具体动作。若用户尚未给目标，简要给出两个不同方向（如答题测验、照片拼贴），只问「你希望用户打开小工具后完成什么事？」收到回答后直接继续向导，无需再输入命令。只有用户要求实现时才开始写代码。

## 快速查能力

用户问“能做什么”“列一下能力”时，第一条回复就给下面的速览，用用户能看到的动作说明能力和限制。无需先问项目背景，也无需先读取全部参考文件。表后附[官方能力清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)及依据日期。

| 想做什么 | 能力与边界 |
| --- | --- |
| 做互动页面和小游戏 | 可以抽签、答题、做动画、画海报。3D 效果取决于设备能否渲染。 |
| 处理照片和影音 | 可以选照片或视频、做拼图。摄像头和麦克风需要授权，保存图片到相册另有版本和权限要求。 |
| 保存进度和成绩 | 可以在支持的版本保存本机草稿和文件。同账号跨设备存档、公开排行榜属于内测，需要平台开放。 |
| 做位置和体感互动 | 支持相应版本时可以在打卡时请求一次定位、振动反馈或随手机转动做互动。定位需授权，无法在后台连续记路线。 |
| 发布和分享结果 | 可以让用户进入笔记或评论编辑器，由用户决定是否发布。平台分享入口仅限支持版本的全屏容器。 |
| 与作者互动 | 支持的版本可以引导用户关注当前作者。赞赏及关闭时的赞赏挽留属于内测，需开通和配置。 |
| 用 AI 生成内容 | 开通内测后可根据文字生成文案。平台 AI 未提供生图或照片识别接口。 |

速览末尾点出最常影响立项的限制：页面不能直接请求自己的服务器，无法通过自建连接实时联机，也不能跳转到任意外部网站。

如果用户点名某类（如“只看存储”），只展开该类，列出关键版本、资格或权限。若明确要“完整清单”“全部能力”或“逐项列出”，直接用[按功能查能力](references/capabilities.md)的全部动作与禁用项分组作答，覆盖渲染、资源与计算、数据、设备、平台互动及限制，不用速览代替明细。只有平台明确限制的项才标“不支持”；找不到依据的项标“待核实”。

**已经知道想做什么**，开发者只需说功能。即使对方直接说“帮我做”，也先主动查清单和对应专节，把用户目标拆成可单独判断的动作。留意数据从哪来、要存给谁、何时触发、是否要在后台运行。把结论用于设计、代码和验收。

## 收到功能需求后

1. 用用户自己的词给出逐项判断。简单需求一两句话即可；复杂需求可列“功能｜可行性｜前提或替代办法”。每个会改变方案的结论附上对应的官方章节。只列本次决策涉及的细节。
2. **可做**的动作给出实现路径。**有条件**的动作给出具体的版本、用户授权、账号开通或容器场景，以及条件不满足时界面如何继续。区分平台公开了接口、当前账号已获资格、该功能已经真机跑通这三件事。
3. **当前不支持**的动作写明文档限制，给出接近原意的选择和代价。**待核实**用于公开资料不足、资格未知或文档冲突：写出已知边界和最小核实办法。不得猜测私有接口或把整个混合需求一次判死。
4. 对“能不能做”直接回答；对“帮我做”继续实现已授权且不依赖未知条件的部分。会改变产品承诺的取舍才交回用户，例如把实时多人对战改成异步比成绩。不把用户没有同意的降级包装成已经实现。
5. 遇到“当前”“最新”、新能力、内测、额度或版本门槛，回查[官方能力清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)并标出核对日期。无法联网就注明依据的快照日期及待确认项。遇到冲突，指出相关专节并采用明确允许的实现。

例如“做一款散步打卡工具，生成纪念海报，退出小工具后也能记录路线”。包内素材可用 Canvas 绘制海报。打卡时可在 9.49+ 请求一次位置，拒绝后让用户手选地点。后台连续轨迹当前不支持；逐次打卡只能得到离散的点。用户要求实现时可先做海报和手选地点，单独说明轨迹的取舍。[定位约束](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s3-12)

## 开始开发

按需要阅读[容器与资源](references/runtime.md)、[平台接口](references/platform.md)或[排错与验收](references/acceptance.md)。登录开发者账号、启动模拟器、生成手机预览、上传、送审、修改作品资料及查询审核状态，使用**小红书小工具 CLI**（`$redapp-cli`）。

1. **做出能离线打开的入口。** 让入口 HTML 先展示内容，用包内相对路径加载外置 JS。检查编译后的 JS、CSS 和依赖能在 Android 8.1 的 WebView 61 上运行。检查实际请求，移除外部字体、CDN 和依赖在运行时发起的联网请求。对可延迟的大资源，按容器规则选择目录并准备加载失败状态。
2. **只在需要的动作上接入平台。** 容器注入 `window.xhs`。读取前逐级判空；有版本要求时同时查客户端版本和具体方法。通用端能力使用 `window.xhs.miniTool`，AI 另走 `window.xhs.AI`。处理成功、失败和用户取消；普通浏览器调试时让纯网页功能继续工作。
3. **用一个完整动作检验实现。** 例如做照片拼贴，让用户选图，先在页面看见合成结果，再点击保存。页面内预览可以用 Blob URL。小图可将 Canvas 导出的 PNG Data URI 直接作为 `filePath` 交给 `saveImageToPhotosAlbum`；大图优先用 `writeTempFile` 换取临时路径。用户点击保存时检查客户端 9.42+ 和所用方法。收到保存成功回执后才提示已保存。拒绝授权时保留拼贴；迟迟未收到回执时保留作品和编辑能力，提示用户先查看相册再决定是否重试。[图片接口与临时文件](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s3-4)
4. **检查最终上传包。** 从 ZIP 根目录核对入口、脚本、大小写与资源相对路径。抽查实际构建产物是否引入内联事件、动态执行、外网地址或超出兼容基线的语法。
5. **分开记录验证结果。** 浏览器验证核心操作和无 SDK 场景，模拟器检查容器适配，真机验证授权、系统弹窗、媒体、前后台恢复以及对应客户端版本。按实际任务记录设备、版本、操作、结果和未测项。
