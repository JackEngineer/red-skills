# 排查运行问题并验收性能

本指南依据小红书官方能力清单第 6、7 章整理，核对日期为 2026-11-19。下文的容器限制来自文档，不代表已经在用户设备上验证。性能措施属于文档建议，示例数值不能充当平台强制门槛。

## 先排查能力和加载错误

按以下步骤复现问题。每项保留触发动作、客户端版本、错误信息与实际结果。官方入口为 [第 6 章 FAQ](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s6)。

1. 文件选择不符预期时，分别测试图片与视频。容器只支持这两类文件，修改 `accept` 无法开放其他文件类型。FAQ 的问题标题提到只能选图片，正文却给出图片和视频范围，不据此承诺特定设备的视频选择行为，需真机验证。
2. 脚本不执行时，检查控制台 CSP 错误。把业务脚本放入包内 `.js` 文件，在 HTML 中用带 `src` 的经典脚本标签引用。移除行内事件属性，用 `addEventListener` 绑定。按 [资源加载规则](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s2-6)复查产物。
3. 接口或线上素材失败时，检查是否残留外部请求。页面不能通过 `fetch`、`XMLHttpRequest` 访问自建服务，也不能直接加载线上资源。把静态数据、字体、图片与脚本装入 ZIP。平台资源优化仍使用包内同源路径，不能改写为 CDN URL。
4. 实时数据需求不可通过 WebSocket、SSE、WebRTC 或轮询自建服务实现。平台 AI 当前提供非流式文本生成，不据此设计流式回答。
5. 第三方库运行失败时，检查动态执行、WASM、网络访问和 Worker 使用。按 [安全限制](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s4)与 [Worker 规则](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s2-8)逐项定位，不能只看构建是否成功。
6. 保存图片或发笔记时，按对应接口检查媒体字段。生成图片可先用 `writeTempFile` 将 base64 转为本地 `filePath`，再调用 `saveImageToPhotosAlbum` 或 `postNote`。网络图片 URL 不受支持，具体字段是否接受 data URL 或本地路径以该接口约定为准。
7. 接入 AI 时，检查 `window.xhs.AI` 是否存在、appId 是否完成内测加白。平台调用无需自建服务或 API key。按 [AI 接入规则](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s3-10)核验具体限制。
8. `window.xhs` 缺失时，先确认是否在普通浏览器。按需求分别检测 `miniTool` 与 `AI`，验证无 SDK 时的降级界面。浏览器模拟成功不等于平台能力通过。
9. 对文档未列出的原生能力停止调用尝试。仅按 [JS API 清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s3-2)设计功能。

## 验证分阶段启动

依据 [§7.1 首屏与分阶段启动](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s7-1)执行以下检查。

1. 延迟或禁用入口 JS，检查标题、用途、规则和必要占位是否仍显示。把能预先确定的内容放入入口 HTML，用少量关键 CSS 和系统字体显示。
2. 恢复脚本后，记录内容首次出现和核心操作真正可用的时刻。游戏另记录首关可玩时间，按钮显示或事件绑定完成不能代替可玩。
3. 使用经典外置脚本的 `defer` 减少解析阻塞。检查执行阶段的长任务，分批准备重资源并让出主线程。
4. 模拟首关准备失败，检查规则保留、状态可理解、重试有效。总量未知时显示阶段，不显示虚假的百分比。
5. 录屏检查加载阶段切换。示例中的棋盘占位可使用 `aria-busy`，状态区可使用 `role="status"`，完成后同步更新实际状态。

## 分开核算包体、加载和解码成本

依据 [§7.2 资源策略](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s7-2)与 [§2.7 平台静态资源优化](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s2-7)执行以下检查。

1. 将首屏必需的小资源与可延后的大图分开。可采用 `critical/` 与 `assets/`，完整 ZIP 仍须包含全部资源。是否参与平台透明分发，按 §2.7 的条件与适用版本核验。
2. 在同一环境对比资源调整前后的核心就绪、详情首次打开与弱网回退。仅在能取得宿主数据时比较主包加载耗时。
3. 团队使用 OSS 管理设计源文件时，在构建阶段下载锁定版本并校验哈希。按显示尺寸转码，只装入所需白名单素材。运行时仍引用包内路径，不直连 OSS。
4. 分别记录 ZIP 字节、解压后文本及资源字节、图片尺寸和解码成本。先缩尺寸、去重，再评估压缩。
5. 估算运行内存时，RGBA8 的 2048 × 2048 单份像素数据约为 16 MiB。额外拷贝、GPU 副本、mipmap 和渲染目标另计。这个数是计算示例，不是容器内存上限。

## 检查构建产物和延迟加载

依据 [§7.3 工程构建](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s7-3)，先确认目标 WebView 与项目锁定版本。以下检查针对最终 ZIP。

1. 列出入口必需模块、桥接能力、后续场景及资源。排查依赖和插件引入的外域访问、动态执行、WASM 与受限 Worker。
2. 分别检查业务代码、依赖、打包器运行时和延迟分片的语法。转译之后仍检查运行期 API、CSS 回退与经典脚本方式，按 [兼容基线](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s2-2)验收。
3. 删除不用的依赖、语言包与素材。检查 tree shaking 是否误删注册逻辑或样式副作用，保留公开桥接字段。避免属性混淆。
4. 仅清理专用输出目录后重建。检查根 `index.html`、文件白名单、静态文件、大小写及 CSS 路径，确认没有残留旧分片。调试映射留在开发侧，交付 ZIP 排除 `.map`。
5. 使用 webpack 5 经典分片时，核验相对 `publicPath`、JSONP 分片加载、IIFE 和 `chunks/` 路径。`target: ['web', 'es2017']` 不能替代源码及必要依赖的兼容转译。增加 runtime 或 vendor 入口后，按产物顺序加载完整入口集合。
6. 将 webpack 示例中的 300 KiB 入口告警作为可调整预算。它不覆盖手工复制的文件，也不是最终 ZIP 限额。独立图片可评估 `asset/resource`，按首屏依赖决定保留位置。
7. 使用 Vite 6 库模式 IIFE 时，核验 `base: './'`、JS 与 CSS 的目标兼容配置、关闭 sourcemap，并复制自定义 HTML 引用实际 JS 和 CSS 文件。合并入口仍有整体读取与解析成本。
8. 不依赖 Vite 6 库模式中的 `assetsInlineLimit: 0` 保留图片文件。该模式会内联导入的静态资源。需参与平台外移的素材应独立复制并用包内路径引用。更换 Vite 主版本时重新核对选项和构建后端。
9. 对延迟编辑器保持选图、预览和基础操作可用。打开编辑器时加载专用脚本与样式，失败后能重试且保留当前图片。比较入口字节、解析执行时间、预览可用时间与编辑器首用时间，再决定是否有限预热或合并小分片。

## 验证框架、组件库与引擎版本

依据 [§7.4 第三方依赖](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s7-4)，为锁定版本建立最小真实场景。依次测最小功能、真实首屏与主要操作、反复进入和退出。

- React 项目保留静态标题与说明。已有构建期预渲染时才评估 `hydrateRoot`，检查初次输出一致、输入不丢失、首屏未被清空或重复渲染。
- Vue 项目检查构建期模板编译、按需导入、稳定 props。大列表用分页或虚拟化，输入时避免全列表重复计算。
- 组件库项目对比全量注册与按需引入后的实际产物。检查无用主题、图标、组件和重复 polyfill，验证动态类名及按需样式仍然生效。记录首次绘制、输入响应与页面切换；若瓶颈在列表更新，继续检查节点和计算成本。
- PixiJS 类引擎检查实际渲染后端与加载器。重复精灵评估图集与批处理，控制滤镜范围、混合切换和动态文字更新。引擎 API 仍受容器文件及请求限制。
- Three.js 类引擎核对渲染器、材质、加载器和扩展组合。文档指出 r163 起 `WebGLRenderer` 仅支持 WebGL 2，不能据此假设容器所有设备可运行。分别验证纹理、模型、解码器与 WASM，按 [图形能力边界](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s5)验证兼容实现。
- 每次升级检查运行时是否经受限接口加载素材，或默认从 CDN 读取解码器、字体。记录运行库、插件、渲染后端与资源格式的版本组合。
- 反复切场景与退出后，检查监听、计时器、渲染循环和 GPU 资源的释放。共享资源仍在使用时不能提前释放。

## 定位 DOM、CSS 和 GPU 卡顿

依据 [§7.5 DOM 与 CSS](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s7-5)，对长列表比较分页或虚拟化前后的强制布局次数、滚动帧间隔与焦点保留。集中读取布局后再批量写 DOM。动画优先评估 `transform` 和 `opacity`，预留图片尺寸，检查大面积滤镜与透明叠加的重绘成本。

依据 [§7.6 游戏与 WebGL](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s7-6)，先区分场景准备、CPU 提交、GPU 绘制与资源回收的瓶颈。

1. 首关只准备必要模型、纹理、Shader 和输入。静态场景按需绘制，连续动画在隐藏时暂停。
2. CPU 提交慢时，固定关卡和物体数量，对比逐对象提交与按材质批处理。记录 draw call、三角形数和 CPU 提交时间。WebGL 1 先检测 `ANGLE_instanced_arrays`，缺失时用普通绘制或静态合并。拆分空间区块以保留裁剪，透明物体保持正确排序。
3. GPU 绘制慢时，固定 CSS 画布与镜头，逐项降低 DPR、全屏滤镜、实时阴影和透明层。对比帧间隔、清晰度和点击坐标。400 × 800 CSS 像素从 DPR 3 降为 1.5 时，缓冲区从 288 万降到 72 万像素，这不意味着帧率必然提升四倍。
4. 可用 `min(设备 DPR, 1.5, sqrt(2000000 / (CSS宽 × CSS高)))` 作为像素预算起点，前提是宽高大于零。1.5 和 200 万均是示例值，须真机调整。改变画布后同步更新 viewport、相机与渲染目标。
5. 首次材质切换卡顿时，减少首关 Shader 变体。支持 `KHR_parallel_shader_compile` 时跨帧查询完成状态，再检查链接结果并实际绘制。缺失时分批准备。记录切换长帧、首关可玩时间与失败日志。
6. 从已验证的低档或中档启动。前台连续渲染时，以多个稳定窗口判断是否持续超预算，再逐档降画质。排除启动编译、后台及按需绘制空闲期，不按单帧抖动切档。30 FPS 对应约 33.3 ms 的帧预算，只是示例目标，输入和业务逻辑也要计入。
7. 记录纹理、几何和渲染目标数量，反复切场景检查是否持续增长。把压缩资源字节与解码内存、显存分开。
8. 前台恢复时重置帧间隔并只恢复一条渲染循环。模拟上下文丢失，确认游戏状态保留、恢复次数有限、失败后仍能操作兼容实现。
9. 避免在生产帧循环中同步回读或频繁查询 GPU 状态。诊断端支持 timer query 时仅少量采样，跨帧读取并丢弃 disjoint 样本。没有计时能力时明确记为未测，不能用 CPU 时间冒充 GPU 时间。

## 留下可比较的验收记录

按 [§7.7 指标与验收](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s7-7)记录以下信息。本文未规定统一通过阈值；具体预算应在项目中确定。

- 固定设备、客户端与容器版本、网络、缓存条件、操作路线和画质。记录改前改后包版本与样本量。
- 分别记录打开到页面可见、可取得的 FP 与 FCP、核心操作可用或首关可玩。宿主未提供容器准备时间时，标记不可观测，不反推为确定数据。
- 记录固定操作的点击响应、前台帧间隔 p95、画质降档及触发条件。应用提交帧数不等于屏幕呈现帧数。
- 覆盖冷启动、暖启动、弱网、离线、前后台切换。资源优化后的首次详情加载需单独覆盖弱网和失败回退。
- 使用同一个最终 ZIP 完成浏览器、模拟器、真机测试，分别报告结果。普通浏览器通过不能替代真实容器验收。
- 将测试状态写为已通过、失败、未执行或不可观测，并附证据。保留失败日志和未实测项，不将方案建议写成性能提升结论。

建议每条记录包含测试场景、设备与版本、包版本、缓存与网络、样本数、测量起止点、指标、实际结果、证据路径和剩余问题。此记录格式为本技能的组织建议，非官方强制字段。
